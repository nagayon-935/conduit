# 管理者・ユーザー分離の導入手順

Conduit は、ブラウザで登録済み SSH 接続先を利用するソフトです。Conduit のログインユーザーと SSH のユーザー名を別に管理し、同じ SSH アカウントを使っても端末・履歴・録画の所有者を分離します。

## 初回セットアップ

1. `DB_PATH` と録画ディレクトリを永続ボリュームに配置します。SQLite のファイルと録画をセットでバックアップしてください。
2. `PUBLIC_URL` をブラウザで利用するオリジンに設定します。本番は HTTPS、`KNOWN_HOSTS_PATH` は接続先と踏み台の既知ホスト鍵を含むファイルを指定します。鍵は信頼できる経路で照合して登録してください。
3. `SSH_ALLOWED_CIDRS` に接続先・踏み台のアドレス範囲を設定します。空の場合はすべての新規 SSH 接続を拒否します。DNS の全候補を検証し、検証済み IP に接続します。ループバックは明示的な開発設定と許可 CIDR がある場合だけ利用でき、リンクローカル・メタデータ宛ては拒否します。
4. サーバーを停止した状態で初期管理者を作成します。

```bash
go build -o bin/conduit ./cmd/server
./bin/conduit bootstrap-admin --login admin --db ./data/conduit.db
```

パスワードは端末に表示せず入力します（12 文字以上）。標準入力からも読めます。引数や環境変数には渡しません。既に利用者がいる DB に管理者を追加する初期化操作は拒否します。

5. サーバーを起動し、`/login` でログインして初回パスワードを変更します。
6. 管理者画面の「接続先」で target、SSH アカウント、必要なら固定の踏み台を登録します。「接続・閲覧権限」でユーザーに権限を付与します。管理者自身の SSH 接続にも接続権限が必要です。

Docker Compose の場合、初回の起動前に次のコマンドを実行します。

```bash
docker compose -f docker-compose.prod.yml build
docker compose -f docker-compose.prod.yml run --rm --no-deps backend \
  ./conduit bootstrap-admin --login admin
docker compose -f docker-compose.prod.yml up -d
```

## 画面と操作

- `/app`: 許可済み接続先の検索、お気に入り、最近の接続、再開できるセッション。
- `/app/workspace`: 複数端末、分割配置、テーマ、検索、指定ユーザーへの閲覧共有。
- `/app/sessions`: 自分のセッションの再接続・終了。
- `/app/logs`: 自分の履歴・録画。`/app/history` も使用できます。
- `/app/preferences`: 個人の表示設定と旧ブラウザデータの消去。`/app/settings` も使用できます。
- `/admin`: DB・接続・録画の状態確認。各メニューでユーザー、接続先、権限、共有、全体の履歴、監査、運用設定を管理します。

タブを閉じる操作は、SSH プロセスの終了とは別です。最後の操作用接続が離れると、既定で 15 分間再接続できます。閲覧者だけが残っても猶予は延びません。通常ログアウトも SSH を猶予期間中保持し、当該ログインの共有・端末接続を閉じます。「自分の SSH をすべて終了する」を選ぶと、他の端末で利用中の自分の SSH も終了します。

ログインは既定で絶対期限 8 時間、無操作 60 分です。端末入力と変更操作は活動として扱います。一覧の自動更新、heartbeat、SSH の出力は無操作期限を延ばしません。認証期限に達しても同じ画面の端末出力は残し、本人の再ログイン後に新しいチケットで再接続します。別利用者でログインすると、旧利用者の端末と配置を破棄します。

共有リンクは `/app/shared/{id}` です。閲覧権限があるユーザーを作成者が指定し、閲覧者もログインします。リンクだけでは接続できません。閲覧側の stdin・PTY resize はサーバーでも拒否します。取消、期限、ログイン失効、ユーザー無効化・閲覧権限取消で閲覧を切断します。

踏み台の通過は登録された接続経路として許可します。踏み台アカウントへの直接ログインは別の grant が必要です。初期版は 1 段だけに対応します。踏み台側でも到達先制限を設定してください。

## 保存・失効・運用設定

ユーザー、ログインのトークンハッシュ、対象・grant・共有・個人設定、履歴、監査は SQLite に保存します。パスワードは salt 付き Argon2id（19 MiB・2 回・並列度 1）でハッシュ化し、形式にアルゴリズム・パラメータを含めます。SSH 資格情報は今回の接続にだけ使用し、ブラウザや DB には保存しません。

同じ DB を複数の Web サーバーや管理コマンドで同時に開く操作はファイルロックで拒否します。SSH・PTY・WebSocket・30 秒の一回限りチケットはメモリ上に保持し、サーバー再起動を越えて継続しません。

管理変更と監査は同一トランザクションで確定します。変更と SSH 登録・WS 接続登録を調停し、取り消し途中のダイヤルをキャンセルします。接続確立後に履歴を保存できない場合は SSH を閉じ、成功レスポンスを返しません。

運用設定で期限、共有期間、録画・保存期間を変更できます。revision が古い更新は `409` で拒否します。期限は既存のログイン・SSH にも反映します。録画の有効・無効を変更した場合は既存 SSH を終了し、新しい録画方針で再接続します。Vault 資格情報、known_hosts、DB・録画パス、公開 URL はデプロイ設定で管理します。

既定の接続履歴は 90 日、監査は 180 日、終了済み録画は 30 日・10 GiB です。毎分、終了済み録画を古い順に削除し、ログの録画表示も更新します。録画中のファイルは削除しません。接続履歴削除の前に対応録画を削除し、24 時間以上前の孤立した cast も回収します。録画中のデータを含めたディスク容量は運用側でも監視してください。

## 旧バージョンからの移行

1. 利用者へメンテナンスを告知し、旧サーバーを停止して DB と録画をバックアップします。
2. 同じ DB を指定して新サーバーを初期化します。旧 `connection_logs` は一度だけ移行し、所有者不明の旧履歴を管理者だけに表示します。SSH のユーザー名から利用者を推定しません。
3. 管理者・利用者・接続先・権限を作成します。管理者画面の「旧プロファイルを確認」でこのブラウザのホスト情報を確認し、無効状態の target/account として登録できます。鍵は取り込みません。踏み台・環境・許可を管理者が確認してから有効化してください。
4. ユーザーの表示設定または管理者の移行ダイアログから、旧鍵・トークン・プロファイル保存データを消去します。旧データによる自動接続は行いません。
5. 旧 `/api/connect`・`/api/session`・`/api/sessions`・`/api/shared/*`・`/api/logs`・`/api/recordings` は `410`、旧 WS token/share 接続は拒否します。`ADMIN_API_TOKEN` は廃止し、匿名の互換 API はありません。
6. 全利用者は再ログインします。以前のライブ SSH、匿名共有は継続しません。再起動時に旧ライブ記録を `server_restart` として終了します。

DB のメタデータは `control_objects` の型別 JSON 行に格納し、ユーザー・ログイン・所有者検索の履歴・監査は専用テーブルを使用します。設計書の論理モデルを維持しながら初期版の migration をまとめています。

## 管理者の復旧

```bash
docker compose -f docker-compose.prod.yml stop backend
docker compose -f docker-compose.prod.yml run --rm --no-deps backend \
  ./conduit reset-password --login admin
docker compose -f docker-compose.prod.yml up -d backend
```

サーバーを止めてから実行します。新しい一時パスワードは次回ログイン時に変更が必要です。復旧コマンドはデータを再初期化しません。停止・再起動に伴いすべての Web ログインとライブ SSH は失効します。

## 開発環境

Vite の同一オリジンプロキシを使う場合:

```bash
export PUBLIC_URL=http://localhost:5173
export CONDUIT_DEV_HTTP=true
export DB_PATH=./data/conduit.db
export SSH_ALLOWED_CIDRS=127.0.0.0/8,172.16.0.0/12
# Vault 設定も指定してサーバーを :8888 で起動
export SERVER_PORT=8888
go run ./cmd/server
# 別の端末
cd frontend && npm ci && npm run dev
```

`CONDUIT_DEV_HTTP=true` は開発用 Cookie とホスト鍵未設定の例外を明示的に有効にします。本番には設定しません。プロキシ経由のログイン試行制限は、`TRUSTED_PROXY_CIDRS` を信頼した nginx の送信元だけに限定し、nginx が上書きする `X-Real-IP` を使用します。未設定なら転送ヘッダーを信用しません。

CLI は直接 Vault と SSH を利用します。この Web の接続権限・共有・録画・監査の管理対象には含まれません。SSO/MFA、グループ、SSH 秘密情報の永続保管、複数サーバーへの分散、再起動を越える PTY は初期版の対象外です。
